# 로하스 오토 (lohasauto)

> **하루 한 사람이 스마트스토어 상품 500건.**
> 그게 이 도구가 존재하는 이유입니다.

상품 하나를 올리려면 사람이 화면을 열고, 카테고리를 고르고, 상품명을 짓고,
태그를 달고, 저장하고, 다음 상품으로 넘어갑니다. 팝업 하나가 뜨는 데 몇 초,
한 건에 몇 분. 하루가 다 가도 수십 건입니다.

이 도구는 그 반복에서 **사람이 판단해야 하는 부분만 남기고** 나머지를 걷어냅니다.
조회는 브라우저 없이 HTTP 로 직접 하고(12칸 점검 844초 → **4.9초**),
근거가 확실한 카테고리는 자동으로 저장하고, 태그는 규칙과 AI 로 후보를 좁혀
사람 앞에 **제안**으로 올려놓습니다. 사람은 보고, 고치고, 승인합니다.

숫자로 확인된 것들입니다.

| | 이전 | 지금 |
|---|---|---|
| 검색 1회 | 약 60초 | **0.2~1.9초** |
| 전체 12칸 점검 | 844초 | **4.9초** |
| 카테고리 저장 | 수작업 | 2,092건 → **미저장 0건** |
| 태그 투입 | 수작업 | LCP 1종당 **10초 안팎** |

우리는 회사의 서버를 함께 씁니다. 빨라지자고 서버를 망가뜨리면
모두의 작업이 멈춥니다. **속도보다 서버가 우선입니다.**

| **수집** | LCP 기본정보·옵션·키워드·카테고리 후보, L코드별 작업상태 |

| **카테고리** | 근거 등급별 자동 저장 + 사람이 골라야 하는 것만 검토 화면으로 |
| **태그** | 로하스 기본 후보에서 규칙대로 고르고, AI 로 안 맞는 것을 거른 뒤 **제안** |
| **검수** | 자동으로 넣은 것을 사람이 훑어보는 화면 (클릭하면 사이트가 열림) |

화면은 일곱 개입니다 — 대시보드 / 상품정보 / 카테고리 / 카테고리 검토 /
미작업목록 / 카테고리 수정 / 태그 검수.

**자동은 어디까지나 제안입니다.** 카테고리 자동 선택 규칙의 정확도를 짐작하지 않고
사람이 저장해둔 367종으로 실측했더니, 후보 1·2위가 접전이면 **74.1%** 였습니다.
넷 중 하나가 틀립니다. 그래서 그 구간은 자동에서 빼고 사람에게 넘깁니다.
재보지 않았으면 555건을 잘못 넣을 뻔했습니다.

자세한 실측 기록과 사이트 동작은 사내 문서에 있습니다.

## 1. 설치

### 실행파일로 쓰기 (파이썬 없는 PC)

`dist/lohasauto/` 폴더를 통째로 복사하고 `lohasauto.exe` 를 실행하면 됩니다.
파이썬을 깔 필요가 없습니다.

```
lohasauto/
    lohasauto.exe          GUI
    .env                   설정 — 반드시 확인하고 쓰세요
    data/banned_words.txt  금지어 사전
    사내망_실행.bat / 외부망_실행.bat
```

> **`.env` 는 실행파일 안에 들어 있지 않습니다.** API 키와 SSH 비밀번호가 들어
> 있어서 exe 에 넣으면 뜯어볼 수 있기 때문입니다. exe 옆에 두고 읽습니다.
> **다른 사람에게 전달할 때 `.env` 내용을 반드시 확인하세요.**

빌드는 이 명령 하나입니다.

```bat
python -X utf8 build_exe.py
```

### 소스로 쓰기

```bat
cd /d S:\python\lohasauto
python -m venv venv
venv\Scripts\pip install -r requirements.txt
```

`.env` 에서 계정과 옵션을 확인하세요.

```ini
LOHAS_ID=계정@example.com
LOHAS_PW=비밀번호
HEADLESS=0            # 1이면 창 없이 실행
PAGE_SIZE=1000        # 한 페이지 조회 개수
MAX_PAGES=100         # 페이징 무한루프 방지
SQLITE_PATH=data/lohasauto.db
MYSQL_ENABLED=0       # 1로 바꾸면 아래 MySQL로 미러링
```

```bat
사내망_실행.bat      회사에서 — 사내 IP 로 직접
```

## 3. 사용 순서

| 단계 | 버튼 | 하는 일 |
|---|---|---|
| ① | **마스터 폴더 스캔** | ss_image 페이지의 '마스터' 콤보에서 폴더명 + 수량을 전부 읽어 DB 저장 |
| ② | **마스터폴더로 지정** | 드롭다운에서 고른 폴더를 작업리스트에 편입 (여러 개 가능) |
| ③ | **작업폴더로 지정** | 작업리스트에서 실제 점검·작업할 폴더 하나를 지정 (★ 표시) |
| ④ | **⚡ 빠른 점검** | 작업대상 한 칸만 조회 — **약 1초** |
| ⑤ | **전체 점검 (12칸)** | 12칸 매트릭스 전부 조회 — **약 5초** |

폴더 패널에는 두 개의 표시 옵션이 있습니다.

- **메인상품(51~59)** — 기본 체크. 폴더번호가 `51`~`59`로 시작하는 광고진행 폴더 66개만 표시
- **모두 표시** — 해제 시 마스터폴더만, 체크 시 전체 92개

### 집계 방식 (실측으로 확정)

이 페이지는 상태를 **셀 텍스트가 아니라 버튼 CSS 클래스로만** 표시합니다.

```html
<td><!-- 대표이미지 -->
  <input class="btn_m btn_mb" value="수정" onclick="editImg('16634146', 1196306)">
<td><!-- 상품정보 -->
  <input class="btn_m btn_mb" value="수정" onclick="editAttr('16634146')">
```

그런데 그 클래스는 **2진값**입니다.

| 클래스 | 의미 |
|---|---|
| `btn_m*` | 최종완료 (대표이미지 승인완료 / 상품정보 저장완료) |
| `btn_z*` | 그 외 전부 (미작업, 이미지작업, 제외, 보류) |

즉 클래스만으로는 `미작업` vs `이미지작업`, `미작업` vs `제외` vs `보류` 를 구분할 수 없습니다.
게다가 **URL 페이징(`/p/2`)이 동작하지 않아** 한 번에 최대 1000행까지만 읽힙니다.

그래서 화면의 **상태 필터 콤보를 직접 걸고 검색해 결과 행수를 세는** 방식을 씁니다.

| select | 담당 컬럼 | 옵션 (value) |
|---|---|---|
| `dest_list` | 대표이미지 | 미작업 `none` / 이미지작업 `done` / **이미지승인완료 `allow`** |
| `dest_attr` | 상품정보 | **미작업 `none`** / 저장완료 `save` / 제외 `exclude` / 보류 `hold` |

대표이미지 3상태 × 상품정보 4상태 = **12칸 매트릭스**로 쪼개어 각 칸을 검색합니다.
칸을 쪼개면 대부분 1000행 미만이 되어 정확히 셀 수 있습니다.
1000행을 채운 칸은 `order=desc`(역순)로 한 번 더 읽어 합집합을 구해 2000건까지 커버하고,
그래도 넘치면 `⚠` 표시와 함께 `capped` 로 기록합니다.

**★ 작업대상 = `dest_list=allow` + `dest_attr=none`** (대표이미지 승인완료 + 상품정보 미작업)

행은 **L코드 단위**라 같은 LCP가 여러 행일 수 있어, 모든 수치를 **행수와 LCP 종수 둘 다** 기록합니다.
상세 탭의 **작업대상 LCP코드 복사** 는 중복 제거된 LCP코드를 클립보드에 넣습니다.

## 3-1. 조회 엔진 (HTTP)

상단 **빠른조회(HTTP)** 체크(기본 켜짐) 상태에서는 브라우저를 아예 띄우지 않습니다.

로그인 쿠키(`PHPSESSID`)만 저장해두고 검색 POST 를 직접 재현합니다.
핵심은 `searchNow()` 가 세팅하는 `action_mode=search` 로, 이 값이 없으면 결과 그리드가 빈 채로 옵니다.

```
POST /manager/commercial/commercial_ss_image/p/1
  action_mode=search           ← 이게 없으면 결과가 안 나옴
  categoryname_select=master
  site_categoryname_search=594. 광고진행-비트마인드
  dest_list=allow              ← 대표이미지 상태
  dest_attr=none               ← 상품정보 상태
  viewnum=100000               ← 1000행 상한 해제
  fc=product_code / order=asc / fv=
```

효과가 큽니다.

| 항목 | 브라우저 | HTTP |
|---|---|---|
| 검색 1회 | 약 60초 | **0.2~1.9초** |
| 전체 12칸 점검 | 844초 (14분) | **4.9초** |
| 빠른 점검 | 약 1~2분 | **0.9초** |
| 폴더 목록 스캔 | 약 60초 | **0.06초** |
| 1000행 상한 | 있음 (역순 병합으로 2000까지) | **없음** (`viewnum` 상향) |

상한이 사라져서 이전에 못 세던 칸도 정확해졌습니다.
예: `이미지승인완료 × 저장완료` = 2,000(상한) → **4,307행 / LCP 514종**.
전체 LCP 763종이 폴더 라벨 `(764)` 와 일치하는 것으로 교차 검증됩니다.

HTML 파싱은 bs4 대신 행 단위 분할 + 정규식을 씁니다.
12MB 응답 기준 **bs4 5.13초 → 0.04초 (128배)**, 결과는 6,795행 전부 동일함을 실측 확인했습니다.

쿠키가 없거나 만료되면 자동으로 브라우저를 띄워 로그인하고 쿠키를 갱신한 뒤 HTTP 로 이어갑니다.
체크를 해제하면 기존 브라우저 방식(느리지만 화면으로 확인 가능)으로 동작합니다.

## 4. 진단 도구

페이지 구조가 바뀌면 **[페이지 구조 덤프]** 버튼을 누르세요.
`logs/page_dump_*.txt` 에 select 목록 · 그리드 헤더 · 앞 15행의 셀 내용이 기록됩니다.

`tools/` 에 이 페이지를 규명할 때 쓴 진단 스크립트가 남아 있습니다.

| 스크립트 | 용도 |
|---|---|
| `dump_once.py` | 폴더스캔 + 페이지 구조 덤프 |
| `inspect_once.py` | 폴더스캔 → 작업폴더 지정 → 수량점검 → DB저장 (CLI 전체 실행) |
| `probe_classes.py` | 상태 셀 CSS 클래스 분포 수집 |
| `probe_map.py` / `probe_attr.py` | 필터 콤보 ↔ 컬럼 매핑 확인 |
| `probe_paging.py` | URL 페이징 동작 여부 확인 |

## 5. 자체 DB 스키마 (SQLite)

| 테이블 | 내용 |
|---|---|
| `folder` | 마스터 폴더 목록. `is_work=1` 이 현재 작업폴더, `is_active=0` 은 사이트에서 사라진 폴더(이력 보존) |
| `scan` | 점검 1회 = 1행. `mode`(full/quick), 전체/대표이미지 3상태/상품정보 4상태/작업대상 수량 |
| `scan_cell` | 12칸 매트릭스의 각 칸 (행수, LCP종수, capped, is_target) |
| `scan_item` | 작업대상 상세행 (LCP코드, L코드) |

`MYSQL_ENABLED=1` 이면 동일 내용이 `LOHASAUTO_FOLDER` / `LOHASAUTO_SCAN` /
`LOHASAUTO_SCAN_CELL` / `LOHASAUTO_SCAN_ITEM` 로 미러링됩니다. **미러 실패는 SQLite 저장에 영향을 주지 않습니다.**

## 7. 참고

- 로그인은 **`send_keys` 우선**입니다. 값이 실제로 들어갔는지 검증하고, 실패했을 때만
  LOHASPIC 원본 방식(클립보드+Ctrl+V)으로 폴백합니다. 덕분에 다른 창을 쓰고 있어도
  로그인이 깨지지 않고, 클립보드도 건드리지 않습니다.
- 상단 **모니터** 콤보로 브라우저를 띄울 모니터를 고를 수 있습니다 (`.env` 의 `BROWSER_MONITOR`).
- 쿠키는 `data/cookies_<계정>.json` 에 저장됩니다 (`.gitignore` 대상). `.env` 의 `USE_COOKIE_LOGIN=0` 으로 끌 수 있습니다.
- `S:` 는 네트워크 드라이브(`\192.168.219.200\betona`)입니다. SQLite 파일 잠금이
  불안하면 `.env` 의 `SQLITE_PATH` 를 로컬 경로(예: `C:\lohasauto\lohasauto.db`)로 바꾸세요.
